# 🏎️ Drive-Thru Survivors · 得来速幸存者

> **麦当劳赛车 × 土豆兄弟 × 得来速武器改装**
> 一款融合街机漂移赛车、Brotato 式自动射击生存和麦当劳 MCP 真实数据的网页游戏。

## 项目概述

开着赛车冲过敌群，用麦当劳餐品改装你的车载武器，看看你能在这条无尽公路上活多久。

- **赛车操控**来自《马里奥赛车》：漂移蓄力加速、碰撞弹飞、速度感十足
- **战斗系统**来自《土豆兄弟 Brotato》：自动射击、波次生存、波间商店、6 槽武器 Build 构筑
- **数据驱动**来自麦当劳 MCP：真实餐品变身车载武器，真实门店变身赛道站点

**目标用户**：麦当劳粉丝与休闲网页游戏玩家。打开链接即可开玩，无需注册与安装；桌面键盘与手机触屏双适配，适合程序员节等活动现场快速试玩与传播。

## 在线部署（Vercel）

仓库已自带 Vercel 适配，链接仓库即可部署，无需改代码：

1. 打开 [vercel.com](https://vercel.com) → **Add New… → Project**，导入 GitHub 仓库 `hexwarrior6/drive-thru-survivors`
2. Framework Preset 自动识别为 **Vite**（Build Command `npm run build`，输出目录 `dist/`），其余保持默认
3. **Environment Variables** 添加 `MCDONALDS_MCP_TOKEN`（open.mcd.cn/mcp 控制台获取，勾选 Production 与 Preview）
4. 点击 **Deploy**

部署后的行为：

- 前端静态资源与 `/api/*` 网关同域；`vercel.json` 把 `/api/*` 重写到 `api/index.ts`，以 Web 标准 `Request → Response` 形式直接运行同一个 Hono 网关（`server/app.ts`，与本地 `npm run dev:server` 完全同一套代码，共享 `server/mcp.ts` 管线，零适配器）
- 函数时长在 `vercel.json` 配置为 120 秒，覆盖快照构建最坏 55 秒的 MCP 管线；需保持项目开启 Fluid Compute（Vercel 新项目默认开启）
- 冷启动后的第一次 `/api/snapshot` 要真实跑完整个 MCP 管线，可能耗时数十秒，属正常现象；同一城市 15 分钟内命中网关缓存
- 未配置 Token 时线上同样自动降级为示例数据，并在游戏内明确标注离线示例

## 当前实现：阶段 0–5（完整闭环）

完整生命周期：标题选城 → 三款特色赛车选择（闪电红 +8% 速度/氮气回复、寒冰蓝冲撞冰冻减速、磁力金磁吸 130/+20% 金币）→ 倒数 3-2-1 出发 → 五波战斗（第 5 波双车道霸王卡车 BOSS）→ 结算与再来一局。车尾散弹炮每 0.38 秒向 360 道路单位内最近的疯狂骑手自动发射 3 颗弹丸，每颗伤害 12，预判移动并独立旋转瞄准；骑手绕到侧面或超过车头仍可继续锁定。炮台不主动清除路锥和购物车，弹速额外获得车速的 30%。首波 45 秒，此后每波增加 3 秒、上限 60 秒；第 5 波 BOSS 无时钟，击破即通关。倒计时结束后清场、发放波次奖励，赛车在约 2.8 秒内沿右侧匝道自动减速停站；点击「驶入下一波」后先用约 2.5 秒汇回主路，再开始下一波，补充 20 氮气。停靠后可购买餐品武器、同名升阶或维修车况；满 6 槽时选择并确认替换，离站汇回主路获得 2 秒无敌涡轮。默认开启自动油门，可以关闭后使用 W / ↑ 加速；S / ↓ 刹车，A D / ← → 转向。按住 Shift + 转向开始漂移，可保持 Shift 并反打方向控制走线；松开 Shift 释放蓝 / 橙 / 紫三级加速。空格冲刺消耗 20 氮气并持续 2 秒。车况耗尽抛锚或击破 BOSS 均进入结算界面，展示总里程、消灭数、最高连击、6 槽终局构筑与本地纪录。

桌面端保留竖向视角，驾驶时保留两侧教学面板与原有赛道布局，底部显示键盘提示。顶部行程面板合并波次倒计时、下一站和金币，底部操作面板集中显示车速、车况、氮气和驾驶操作，信息与操作使用实色底板，外沿以短距离阴影渐变和轻圆角衔接赛道；暂停与声音按钮在顶部组成同一个工具组，与金币留出独立间距，本波剩余、车况和氮气使用带标签的加粗进度条，漂移蓄力和冲刺反馈在底部面板上方按需浮现，危险和进出站提示共用一个提醒位。里程、击杀、漂移统计与自动油门开关位于暂停面板。移动端游戏铺满动态视口，页面无滚动，按安全区留出操作空间；支持多点触控，底部方向、减速、漂移和冲刺按钮高度为 64 CSS px。P / Esc 暂停，R 重置，M 切换声音；页面失焦或切到后台自动暂停，回到页面后手动继续。声音在首次交互后解锁，由 Web Audio 实时合成。

- 桌面使用 450×800 逻辑画布；手机保持 450 逻辑宽度，按屏幕比例扩展纵向场景。Phaser FIT 等比缩放，赛车不拉伸；WebGL 优先、Canvas 自动降级。
- 固定 60Hz 物理步长与位置插值；512 个预分配粒子精灵，饱和时丢弃新粒子。
- 由直道、长右弯、长左弯和连接段组成连续路线；道路曲率影响航向与速度相对道路的关系，保留轻度回正辅助。
- 道路、赛车、路边景物和粒子共用简易透视投影；碰撞在道路坐标中处理。路线进度独立于绘制，波次末由状态机控制进站。
- 赛车、树木、积木楼和门店纹理由代码绘制；配色、几何与音效包络参考关联项目，未引入外部图片、字体或音频。
- 路障锥静态阻挡、购物车横穿、疯狂骑手从后方追踪；命中闪白并浮出伤害数字，击杀爆破并掉落价值 1–3 的金币。路面金币进入车身 80 逻辑像素范围后自动磁吸；追兵战利品直接飞回车身，避免击杀发生在后方而无法领奖。
- 骑手以小队从车尾进入：前 15 秒每组 2 名，此后每组 3 名；有转向惯性，固定巡航速度约 394 道路单位/秒，冲刺能真正拉开距离。骑手车况 80；同一轮散弹近距离可集中命中 3 颗，远处通常仅中 1 颗，聚拢的追兵可以被同一轮散弹击中。前方路障单列生成，留出变道空间。赛车位置略向上移，并收紧上方仪表，为前方避障和车尾追击同时留出视野。
- 撞击伤害为 `36 × 当前绝对速度 / 340`；蓝 / 橙 / 紫漂移释放期间再乘 2 / 2.5 / 3，氮气期间乘 2，倍率取较高值。普通碰撞扣车况并给予 0.5 秒保护；冲刺撞击不扣车况，车况耗尽可重新开局。
- 弹丸 256、敌人 128、金币 128、粒子 512、伤害飘字 64 组均在开局预分配，池满不扩容；金币池满时合并掉落价值。飘字使用启动时缓存的数字位图，闪白纹理同时兼容 WebGL / Canvas。
- 弹丸使用固定空间网格粗筛和扫掠碰撞，避免高速穿透；战斗更新没有 `new`、对象 / 数组字面量或闭包创建。这里的零 GC 指游戏实体热路径无临时对象分配，Phaser、DOM 和浏览器仍可能进行内部内存分配和垃圾回收。
- 网关已开放只读 `/api/snapshot`，复用 6 项白名单 MCP 工具；Token 只在服务端使用。前端点击发动引擎时按城市加载一次快照，整局固定，波间不轮询。无 Token 返回示例；连接失败时前端明确标注离线示例，服务端真实查询错误仍返回对应错误码。
- `npm run dev` 提供只读 `window.__driveThru` 调试状态；生产构建不包含此接口。

阶段 0/1 验收覆盖桌面 Chromium、390×844 手机尺寸及多点触控模拟、强制禁用 WebGL 的 Canvas 路径。弯道原型另有路线接缝、投影与弯道物理检查。真机触感与扬声器听感仍需实际设备体验；固定物理步长不代表所有设备都已验证稳定 60 FPS。

### 阶段 2 验证

`npm test` 覆盖追兵索敌、后向弹道与射速、移动目标预判、冲刺拉开追兵距离、追兵战利品返还、高速弹丸单次命中、三类敌人、撞击倍率与保护、80px 磁吸、对象池满载、45 秒波次与进站、热路径分配检查以及 10 分钟模拟时间的对象池复用。`npm run build` 执行严格类型检查与生产打包。

开发模式访问 `http://127.0.0.1:5173/?stress=1` 并发动引擎可复现满载场景：持续补齐 48 个敌人、96 发弹丸和数百粒子，保留真实命中与掉落逻辑；此模式锁定车况、停止波次计时，仅用于性能检查。只读 `window.__driveThru.combat` 包含活跃 / 可见实体数与命中统计。该压测入口与调试接口不在生产模式启用。

2026-10-24 本机验证：Codex 内置浏览器 541×823 与 390×844 模拟视口，预热 120 帧后各采样 600 帧，均为 **60.00 FPS**，P95 帧时间 **<18ms**，>25ms 帧数 **0**；最小可见实体数分别为 **46 敌人 / 89 弹丸 / 481 粒子**、**48 / 96 / 480**。390×844 页面无横纵滚动，四个触控按钮高度均为 64 CSS px。高负载运行过程中，Chromium 强制 GC 后 JS 堆由约 29.5 MB 到 28.6 MB，未观察到持续增长。外部浏览器窗口被遮挡时存在约 30 FPS 的呈现限速，应在可见前台复测；以上结果不代表所有真机均已完成性能验收。

波次进站浏览器检查使用 QA 注入将首波缩短到最后 1 秒，确认停车后进度 / 金币冻结、奖励仅发一次，以及点击继续进入 48 秒的第 2 波；真实首波 45 秒与后续 60 秒上限由固定步长测试覆盖。上述注入仅发生在临时测试标签，不属于游戏代码。

另已强制禁用 WebGL，验证 Canvas 路径的自动射击、击杀、金币掉落与伤害飘字。

### 公路追逐生存原型

基础回合检验同一套后置散弹下的驾驶选择：变道避开障碍、引导有转向惯性的追兵聚拢、贴近提高散弹命中数、受压时冲刺拉开距离。手机可按住「减速」让追兵进入近距火力范围，桌面使用 S / ↓；需承担被追上的风险。HUD 根据距离提示「远距牵制」「近距散弹」或「追兵贴身」。后续不同武器再改变驾驶策略，阶段 3 在此基础上增加餐品装备种类。

`tests/prototype.test.ts` 使用相同的 45 秒波次、装备与真实驾驶物理对比两种脚本输入：一直直行约 41 秒耗尽车况；避障并在追兵贴近时使用冲刺可完成整波，剩余 55 车况。该结果是确定性模拟的玩法回归检查，不是玩家试玩结论。散弹另有近距 / 远距命中以及聚拢 / 分散追兵的对比测试。

散弹原型复测（2026-10-24）：34 项测试与构建通过。390×844 模拟视口下，预热后采样 600 帧，平均 60.00 FPS、P95 <18ms、>25ms 帧数 0；至少可见 48 敌人 / 96 弹丸 / 481 粒子，浏览器无错误或警告。五个触控按钮均高 64 CSS px，最窄约 55 CSS px；触摸按住减速实测速度约 302 → 111，释放后恢复至 207 并继续加速。仍需真人试玩判断聚怪、贴近和脱身的节奏是否有趣。

### 得来速出口与停靠区

站点采用「两条通行车道 + 原右侧车道改为维修区」的形态，道路总宽度保持不变。波次结束前 3 秒出现固定在道路坐标中的入口牌；波次结束后赛车自动完成变道，在低隔离墙开始前进入右侧车道，沿维修车道减速停靠。入口和出口使用黄色斜纹标识分流，停靠位用白色停车格与棋盘格标识；原跨车道门架移除，服务亭与扳手标识位于外侧路缘旁。进站时镜头平缓右移，底部面板留出站点视野；离站时沿维修车道前进，通过隔离墙末端后恢复三车道驾驶。

全部资产在启动时用程序化几何与缓存文字生成，站点对象预分配；每帧不创建纹理、文字、补间或临时几何对象。开发模式 `http://127.0.0.1:5173/?preview=pit` 可快速预览一次进站和出站，正常地址仍保持完整波次。


### 阶段 3：得来速武装补给

`npm run dev` 与 `npm run dev:server` 分别启动前端与只读网关。真实数据需要在本机 `.env` 设置 `MCDONALDS_MCP_TOKEN`（参见 `.env.example`），重启网关；禁止使用 `VITE_` 前缀。未设置 Token 时 `/api/snapshot` 直接返回 `demoSnapshot()`，无需配置即可试玩。开局只需输入或选择起始城市（默认上海），也可点击骰子随机选城；系统自动查询并安排沿途停靠，接口仍保留可选 `area` 参数供内部查询。整局重开复用已取得的快照；刷新回到标题后重新获取。

每站优先展示该店的 3 款差异 / 风味餐品，其余已核价单品可展开选购，每卡一份库存。虚拟金币价为 `ceil(单件最终报价分 / 100)`，明确区别于真实支付；示例商品、价格和门店均为游戏示例。真实快照只采用 `calculate-price` 整数分，排除套餐轮次；有效单品不足 3 款的门店不能进入快照。保留 15 分钟 / 20 项 LRU 缓存、并发请求合并、限流、8 秒单次 / 55 秒构建超时和夜间预约菜单参考标签。前端不加载菜单图片或其他外部美术资源。

按商品名称区分汉堡炮台、辣椒喷射器、薯条散射枪、鸡块地雷、可乐喷泉、冰冻射线及咖啡 / 甜品被动。同名餐品升级至 Lv.3，满级拒绝购买；满槽新购先选择旧槽再确认，确认前不扣金币，可取消。初始装备沿用阶段 2 已验收的后置散弹炮，不可升级，可替换。维修消耗 10 金币回复 30 车况（上限 100）。出站沿已有维修车道汇入主路，再开始完整 2 秒无敌涡轮，不扣氮气。

### 城市出发与随机真实门店

开局只保留城市输入框、骰子按钮和「发动引擎」。提供 40 个常用城市候选，也支持输入其他城市名；骰子从候选城市中随机选择并避开当前城市。实际可用得来速与菜单取决于官方返回；查询失败或无 Token 时明确使用示例模式。紧凑面板沿用奶油黄、棕色描边、金黄骰子和橙红出发按钮。

不要求输入店名、指定首站或选择下一站。网关自动使用城市名检索得来速，随机预载最多 4 家可用门店的菜单，优先营业中门店。这个上限用于控制首次查询耗时，并非全市门店数量或目录。15 分钟缓存期间共用该路线池；每次新开局重新随机排定停靠顺序，在访问完池中门店后重新洗牌，并避免相邻两站重复（仅一家可用店时除外）。HUD 与商店显示实际到站店名、地址和餐品。

菜单服务先比较候选店的完整可识别单品名，以差异餐品和名称中的新品 / 限定 / 风味标记优先核价，并保留类别覆盖。每店最多尝试 18 款；仅通过单品详情过滤和整数分计价的餐品可购买，复杂套餐仍过滤，因此不是完整菜单。商店保留 3 张推荐卡，其余已核价单品可展开选购。

「菜单差异 · 1/4 家」仅表示商品名在本次读取的 4 家候选菜单中的 1 家出现，不代表全国独家、官方特色认证或永久在售。比较发生在截取核价名单前，避免因报价筛选漏项而误标。
