# 武器系统重构方案：餐品即武器，品类成家族

日期：2026-10-26  
状态：设计提案，尚未实施。本文中的新机制、数值和验收阈值均为待验证的设计目标。  
范围：武器身份、升级、酱料、车辆模块、商店构筑及必要的战斗配套。

## 1. 方向与结论

建议将当前系统推进为：**具体餐品决定独立武器，食品品类决定武器家族，酱料提供跨武器组合，车辆模块连接驾驶动作。**

内容目标是 **32 件独立战斗武器**，不包含等级、升级分支、酱料组合、被动模块及大小份规格。不同汉堡应对应不同的炮，不同薯类应对应不同的射击／切割武器。门店的餐品差异要直接成为玩家探索新武器的理由。

武器数量与机制质量同时作为目标。换装后应产生不同的判断，例如：

- 重炮：等敌人排成一线，短暂对齐再开火。
- 回旋武器：变道改变回程路线，让同一轮弹丸扫过另一组敌人。
- 尾焰：让追兵进入有效距离，用漂移铺出燃烧路径。
- 地雷：先决定走哪条线，再让追兵踩进自己留下的陷阱。
- 冰冻：控制危险目标，等待安全撞碎的机会。
- 导弹：先保持锁定，再抓住 Boss 的恢复窗口爆发。

**交付方向是几十件餐品专属武器；三件原型仅用于验证基础系统，不能作为最终内容规模。** 按 3 件技术原型 → 12 件可玩武器 → 32 件内容目标分批制作。每一批都要验证同品类内的差异，而不是每个品类只挑一件代表。

武器可以共享攻击基础组件，不必每件重造一套引擎；但不能只有名称、贴图、颜色和倍率不同。也不要求 32 件各自对应完全不同的驾驶操作：同一驾驶流派内，可以通过射击节奏、目标偏好、弹道和组合方式形成不同选择。

## 2. 当前系统盘点：以工作区代码为准

### 2.1 实际结构

当前工作区包含未提交的酱料和变体实现；本次将它们纳入现状，而非只分析已有 Git 提交。没有修改这些实现。

| 层面 | 当前实际行为 | 主要依据 |
| --- | --- | --- |
| 武器槽 | 1 前炮台、1 后炮台、3 辅助位；另有始终开启的内置散弹 | `ShopSystem.slots`、`WeaponSystem.configure` |
| 类型 | 13 类，含初始散弹；其中有主动伤害、被动回复、速度和召唤 | `weaponMapper.ts` |
| 变体 | 28 个美术变体；多变体家族有固定效果表，包含分裂、回旋、波浪及数值修正 | `foodArt.ts`、`variantForms.ts` |
| 升级 | 最高 Lv.5；相同变体可以跨商品名升阶，不同变体需要替换 | `ShopSystem.equipped/buy` |
| 酱料 | 12 种；第 5/10/15 波 Boss 后三选一，最终 Boss 后直接结算 | `sauces.ts`、`GameScene.ts` |
| 叠加 | 多种酱料可以共存；同种效果使用位掩码去重，并非重复持有叠层 | `equipSauce`、弹丸 traits 合并 |
| 随机性 | 商店有洗牌；酱料候选由波号及已有酱料集合确定，没有独立的本局种子 | `ShopSystem.open`、`sauceOffersFor` |
| 局长 | 20 波、4 次 Boss；普通波 42–50 秒；完整局长受 Boss 和商店停留影响 | `balance.ts` |

旧文档存在“6 个自由槽”“Lv.3 封顶”等历史描述，不能用来推断当前可行构筑。现有图鉴内部也混用了新旧规则；例如同时装备汉堡和薯条的旧示例，已经不符合当前前炮台只能放一件的限制。

### 2.2 武器的真实差异与剩余问题

| 当前类型 | 已有差异，值得保留 | 仍需解决的问题 |
| --- | --- | --- |
| 内置散弹 | 自动预判追兵，近距离多弹命中，360° 索敌 | 始终存在且接受弹丸酱料，可能持续主导追兵战，掩盖换装收益 |
| 汉堡炮台 | 前方预判射击、穿透；变体有重弹、弹射、分裂等 | 缺少需要玩家经营的开火窗口，成长主要体现为输出变大 |
| 薯条散射 | 前向扇形、多弹、减速；存在波浪和回旋弹道 | 扇形和弹数可能比回旋路线更抢眼；回程能否形成独立玩法尚需验证 |
| 制导飞弹 | 追踪选定目标，等级提高齐射数 | 当前发射索敌是前方最近目标，没有明确的 Boss 优先规则 |
| 辣椒喷射 | 后向持续伤害、灼烧、宽弧与强灼烧变体 | 与追兵距离有关系，但漂移、速度还没有成为专属攻击规则 |
| 鸡块地雷 | 留在道路坐标、接触引爆、爆后减速区 | 不保证有目标踩入；对前方 Boss 的贡献缺少清楚解释 |
| 冰冻射线 | 单体控制与群体缓速的差异，冰冻撞碎联动 | 挂在后槽却只向前索敌，身份与装备提示不一致 |
| 可乐喷泉 | 周身击退、连锁碰撞、爆炸气泡 | 兼具伤害和防御，容易成为普适补强；应收敛为明确的控场模块 |
| 咖啡／绝境 | 氮气、极速、低血条件收益 | 主要修改属性，尚未形成清楚的动作循环；低血玩法需要独立风险回报设计 |
| 回复／护盾 | 周期回复、击杀回复、磁吸、反伤和环绕 | 多种功能挤在同一类装备中，容易变成“越高等级越全能” |
| 僚车 | 跟随侧翼独立射击 | 主要仍是额外自动火力，尚未建立编队或走线价值 |

### 2.3 为什么“代码有区别”，玩家仍可能觉得一样

以下是基于代码的设计判断，不能代替真人试玩结论。

**第一，差异没有持续转化成驾驶决策。** 多数装备只需买下并等待自动结算。射程、弹数、灼烧颜色有变化，但最优操作仍可能是同一套避障和冲刺。

**第二，公共火力可能盖过特色火力。** 散弹不占槽、不可拆，升级后的尾部武器是在已有追兵输出上做加法。它有保护新手的价值，但需要测量其伤害占比，不能默认其存在没有成本。

**第三，全局强化会稀释原生特色。** 重弹、弹射、灼烧同时也是变体身份。所有弹丸最终都能附上相同特征，容易把前期差异覆盖掉。现有 `sauceBits | variantBits` 还意味着自带弹射再选弹射酱料不会自然增加一层弹射收益，与图鉴的“弹得更欢”并不一致。

**第四，成长的转折来得晚。** 若首个规则强化只在第 5 波 Boss 后到来，玩家需要经过数分钟和首场 Boss 才见到酱料系统。早期重开还会遇到相同的首组酱料候选。

**第五，购买和战斗的承诺不完全一致。** 冰冻后槽实际前向索敌、导弹文案称锁定霸王却没有目标优先级，以及部分渲染范围未读取变体修正，都会削弱玩家建立因果关系的能力。

**第六，敌人考题有限。** 当前主要敌人是路锥、横穿购物车、追兵和 Boss。新增十种弹丸，若仍在解决同一种距离和血量问题，收益有限。

## 3. 参考游戏：取什么，如何转译

### 3.1 《霓虹深渊》：武器发现与道具协同共同构成内容

Veewo 官方介绍强调被动道具之间的叠加，以及组合让每局体验变化。这支持本方案的组合层，但不能据此把基础武器收缩到每品类一件。对于本游戏，发现一款特色食品就获得一件新武器，本身也应是一种奖励。[官方介绍](https://www.veewo.com/neonabyss)

本方案不以未经核对的《霓虹深渊》武器总数作为依据，也不把其道具总量等同于枪械数量。32 件是依据本项目餐品覆盖与内容制作目标提出的规模。

转译到本项目：武器提供稳定、可辨认的基础行为；酱料改变行为的一部分；车辆模块连接漂移、冲刺和战斗触发。玩家能预期一部分效果，又有尝试新组合的空间。

例如“回旋薯刃 + 甜酸酱”应产生可观察的二次扫场路线；“尾焰 + 漂移模块”应留下与驾驶轨迹对应的火带。它们都是本项目的原创提案，不是对参考游戏现成武器的复刻。

不直接照搬官方所说的无限道具叠加：本游戏有狭窄道路、手机视野和固定对象池，需要限制衍生次数与画面密度。追求的是组合结果丰富，不是实体数量没有上限。

### 3.2 《土豆兄弟》：学习自动攻击下的取舍

官方页面确认其默认自动攻击、最多六把武器、波间购买，以及通过物品与特性形成构筑。它提供了“战斗专注走位，暂停阶段专注选择”的参考。[官方介绍](https://store.steampowered.com/app/1942280/Brotato/)

本项目保留自动攻击和波间商店，但将自由走位转译成道路上的距离、变道、刹车和漂移选择。武器数量、槽位和成长公式不必照搬。这里没有使用未经核实的商店概率或特定版本数值作为平衡依据。

### 3.3 明确推荐

以《霓虹深渊》的组合变化为主，以《土豆兄弟》的波间取舍为辅，形成“驾驶构筑”。不新增手动瞄准，不在本轮加入新的主动技能按键，也不同时扩展宠物养成、局外数值成长或复杂套装。

## 4. 新系统结构

### 4.1 保留五槽，重新分清职责

| 装备层 | 容量 | 职责 | 选择代价 |
| --- | --- | --- | --- |
| 前武器 | 1 | 前方输出、Boss 战主火力 | 在多件餐品专属武器中选择，比较弹道、节奏和目标偏好 |
| 后武器 | 1 | 追兵处理，定义诱敌和脱身方式 | 在持续喷射、陷阱、控制、旋转切割等具体武器间取舍 |
| 车辆模块 | 3 | 改变驾驶与战斗的连接方式，或补充续航 | 每次补容错都挤占进攻／资源模块 |
| 酱料 | 独立收藏，首版最多 4 包 | 改写兼容攻击的规则 | 三选一且每类有兼容边界 |

同局双武器允许互补，但不能让单件装备包办单体、群体、控制和回复。玩家可以偏前炮，也可以以后武器清追兵为核心；后者仍须有基础前炮应对 Boss。

### 4.2 内置散弹的处理

推荐将其改为**可替换的初始后槽武器**。获得新后武器时，替换散弹，而非继续叠加。保留其已验证的近距多弹命中特性，作为入门装备；不计入 32 件餐品专属武器的数量。

为避免新玩家突然失去保底能力：

1. 开局保留初始散弹；第一站提供一次免费的基础前炮安装，明确标为游戏服务。
2. 首次替换后槽前显示两件武器的距离与打法对比，可播放短预览。
3. 第一轮保证玩家能拿到一种可用的前向火力；不能把 Boss 输出能力完全交给菜单随机性。
4. 原型阶段对比“散弹常驻”和“散弹可替换”两组配置。若去掉常驻火力只增加挫败、没有增加策略，先降低常驻散弹的成长兼容性，再评估完全替换。

免费前炮属于统一的初始装备补全，不影响真实餐品的标价，不假装是门店赠品。

### 4.3 具体餐品绑定独立武器，技术定义与美术资源分离

现状：商品名 → 武器类型 → 美术变体 → 从美术 key 推导机制。

建议：商品 → 标准化餐品身份 → 餐品专属 weaponId → 武器定义；武器定义引用家族与攻击组件，商品图和弹丸图由展示资源表提供。

- 使用稳定的战斗 ID，升级、存档、酱料兼容都不依赖贴图 key。
- 巨无霸、双层吉士、麦香鱼等独立配方，各自绑定独立武器。不得因都含“堡”就合并为贯穿炮。
- 长薯条、扭扭薯、薯饼等不同形态，各自绑定独立武器。不得因都含“薯”就合并为回旋刃。
- 同一餐品的大小份、加量、包装别名可归为同一餐品身份；例如中薯和大薯不强制制造两件假差异武器。真正不同的食材、配方和形态优先独立设计。
- 同一件武器的 Lv.1–5 是纵向成长；其他餐品武器是横向选择，不应购买麦香鱼却自动给巨无霸升阶。
- 未收录新品要显式进入待映射名单，不得只靠品类或名称哈希声称已有独立武器。临时通用映射必须标注“通用改装”，不计入独立武器数量；正式支持该特色餐品前补齐专属设计。

标准化需要保留关键配方词，不能把“辣”“鱼”“双层”“板烧”当成可删除修饰语。跨门店相同餐品使用同一武器；同一门店不同配方有不同武器。由此，门店差异影响可获得的武器集合，而不是给同一把炮换商品标题。

## 5. 餐品专属武器目录：目标 32 件

### 5.0 内容分布与候选表

目标分布：汉堡／早餐主食炮械 10 件、薯类 6 件、鸡肉小食 4 件、饮品 8 件、甜品 4 件，合计 32 件，全部具有直接战斗能力。车辆模块另计，不用回复泵、速度加成等被动凑足数量。

以下餐品名称用于设计映射示例，**不代表已确认某店或当前市场在售**。特色薯类及其他候选需要用真实菜单校对；如果没有对应商品，保留为储备设计，或换成实际发现的特色食品再重新设计，不伪造门店商品。目录目标是 32 件正式支持的武器，不能把未映射的储备条目当成已完成内容。

W01 与 W08 的差别必须是“在飞行途中穿过目标”与“蓄能后瞬时打线”；W03 与普通爆破酱的差别是“持续集火满足黏附阈值”。这些不是更换弹丸图片就成立的武器。

### 同类武器的差异验收

每件正式入库武器至少在以下维度中的两项与同家族最近似的武器不同，其中至少一项必须是机制差异：弹道／攻击几何、发射与结算节奏、目标优先级、触发与资源循环、驾驶配合、酱料协同方式。视觉和音效辅助辨识，数值倍率不能单独作为机制差异。

采用“先不加酱料、同等级、相近预算”的并排测试。玩家应能辨认拿到的是哪件武器，并说明适合打什么目标、如何发挥。这样允许 32 件武器复用基础组件，同时确保商店里三种汉堡真的是三种选择。

### 六件代表武器的深入设计

下列六件用于展示如何把目录条目展开为可实现规格，**不是全部武器列表，也不是每类餐品的统一替代品**。每件从 Lv.1 就必须有招牌机制。距离、持续时间、伤害尚未定稿，先用现有道路单位与固定步长校准。

| --- | --- | --- | --- | --- |
| 巨堡贯穿炮 | 前 | 重弹沿窄线贯穿，不任意追踪 | 对齐车道，把目标排成线 | 横移目标容易躲开，空炮恢复慢 |
| 扭扭薯回旋刃 | 前 | 弧形出击后回到车辆，去回程各有一次命中机会 | 变道牵引回程扫过第二片区域 | 单次直击弱，高速直行可能接不到理想回程 |

### 5.1 巨堡贯穿炮：用直线换取重击

**基础循环：** 看到前方纵向队列 → 对齐 → 重弹贯穿 → 冷却期间转向避障。炮口允许有限修正，但不能用全角度自瞄消除对齐价值。

Lv.3 分支二选一：

- **压路重炮：** 贯穿增加，每穿过一名敌人保留更多后续伤害；射击间隔更长。
- **夹心破甲：** 贯穿减少，集中命中同一重型目标后施加短暂破甲，前后武器都可获益。

Lv.5 强化所选分支：压路炮贯穿终点产生一次窄向冲击；破甲炮在标记结束时引爆剩余装甲碎片。两者都不变成全屏清场。

协同：冰冻稳定目标位置；减速方便排线。反协同：过强的周身击退可能把敌人推出贯穿线。商店应显示这一取舍。

### 5.2 扭扭薯回旋刃：让弹道跟着走线

**基础循环：** 发出少量清晰可读的薯刃 → 向另一侧变道 → 回程形成斜切 → 接回后进入下一轮。首版减少同时在场数量，优先保证看得清回程。

去程和回程分别记录命中，允许同敌每程各命中一次；不能靠一个弹丸在车旁反复重叠造成无限伤害。接回收益是缩短下一轮冷却，漏接也会超时回收，不能永久卡住武器。

Lv.3 分支：

- **宽弧收割：** 去回程间距扩大，擅长侧向敌群；单体直击降低。
- **回手连斩：** 接回后下一轮更快，擅长连续走线；未接回时没有这项收益。

Lv.5 分别强化回程覆盖或连续接回奖励；不同时增加弹数、爆破、灼烧和控制。甜酸酱可以让去程碰路沿后提前折返，但不会额外重置命中次数。

### 5.3 麦辣标记火箭炮：用稳定窗口换爆发

**基础循环：** 自动选择前方 Boss／重型目标 → 锁定指示逐渐完成 → 齐射 → 重新找走线窗口。没有 Boss 时才按威胁与距离选择普通目标。

锁定区相对道路而非车身瞬时朝向，避免普通转弯打断；较大的横移才会失去锁定，给予短暂宽限，不能要求玩家冒着撞障碍的风险完全不转向。

Lv.3 分支：**单点破甲**提高对锁定目标的集中伤害；**多重标记**可分配多个目标，但降低单体效率。Lv.5 分别强化破甲窗口或已锁目标的分弹分配。

弱点必须保留：追踪不等于瞬间命中，导弹转向有限，失去目标后不能无限寻找替代目标。Boss 战防御动作始终优先于蓄满锁定。

### 5.4 板烧炙烤尾炮：以距离与漂移管理持续输出

**基础循环：** 适度减速让追兵贴近 → 转向／漂移把火带铺进追兵路径 → 危险时冲刺脱离。火带留在道路坐标，不跟着车身移动。

Lv.3 分支：**长燃火带**适合持续引导，喷口直伤降低；**过热喷口**短时间贴近爆发，随后强制冷却，不擅长长时间铺场。Lv.5 分别强化火带连接或冷却后的爆发。

火带和直接喷射共享一次伤害预算，不能重叠十段就造成十倍伤害。同一目标的灼烧取较强来源并刷新时间，首版不叠层。

它对 Boss 的作用来自清理后方压力、触发驾驶模块，为前炮争取稳定窗口；首版不为了直接打到前方 Boss 而取消后向身份。

### 5.5 麦乐鸡雷阵：把道路变成准备好的武器

**基础循环：** 在一侧布雷 → 换线引导有转向惯性的追兵 → 等追兵进入雷阵。正常自动布雷，不增加投掷按键。

Lv.3 分支：**连环雷阵**允许一枚雷激活相邻少量雷，擅长群体；**黏附重雷**将最近一枚雷投向进入近后方区域的重型目标，擅长单点。后者仍需目标靠近，不能变成第二套全距导弹。

Lv.5 强化连爆长度或附着后的延迟重爆。每枚雷只能引爆一次；同一连爆链有总长度上限。未触发雷到期回收，不掉金币，不返还触发资源。

对前方 Boss 的弱点由前炮补齐；Boss 召唤的追兵是雷阵的有效目标。禁止因装备了雷阵就让 Boss 永久不召唤支援。

### 5.6 冰茶锁冻器：控制后选择处置

**基础循环：** 自动选后侧最迫近的追兵 → 累积寒意 → 短暂冻结 → 冲刺撞碎或离开。锁定对象和累积进度可见，不能仅用蓝色飘字表示控制。

Lv.3 分支：**深冻单锁**更快控制单个威胁、冻结更久；**冰雾路障**改为后方短范围缓速区，但不完整冻结。Lv.5 分别强化一次撞碎冰爆或区域控制持续性。

普通敌人解冻后获得短暂控制抗性；Boss 不完整冻结，只短暂降低横向机动或积累弱点，且不能消除侧撞预警与闪避要求。

冰冻撞碎只有玩家冲刺／漂移保护期间可作为安全处置；普通低速碰撞仍可能受伤。卡片必须写出这一条件，避免鼓励无保护撞车。

## 6. 升级：保留五级，让中途有方向选择

| 等级 | 职责 | 示例 |
| --- | --- | --- |
| Lv.1 | 立即拥有武器身份 | 回旋刃已经能折返；地雷已经能布路径 |
| Lv.2 | 改善稳定性和操作容错 | 回旋接取范围略增；雷的有效存在时间略增 |
| Lv.3 | 选择一个互斥分支 | 贯穿覆盖或集中破甲 |
| Lv.4 | 加强所选路线 | 强化分支效率，不补齐所有弱点 |
| Lv.5 | 分支招牌时刻 | 更明显的一次回程收割／连爆，仍有触发条件 |

同一餐品身份／weaponId 的商品可作为升阶材料，例如同款不同规格可以升级；不同汉堡、不同薯类的武器不能自动互相吞并。新增“游戏改装服务”作为材料不出现时的成长兜底。服务价格单独列示，不篡改餐品报价。

需要横向换武器时，必须明确进入替换流程，预览新武器的攻击方式。玩家购买麦香鱼，是选择鱼跃跳弹炮，不是给巨堡贯穿炮增加一级。

分支在进站选择，暂停战斗；当前选择与后续效果始终可查看。首版一局内不重选分支，降低界面复杂度；换成另一原型时分支不继承。替换经济补偿见第 9 节。

## 7. 酱料：从通用加成改为有边界的规则组合

### 7.1 获取时间与随机规则

- 首次三选一提前到第 2 波结束，作为“游戏调味奖励”，让首轮 Boss 前就出现第一次组合。
- 第 5/10/15 波 Boss 后继续各选一次，最多 4 包；第 20 波仍直接结算。
- 新局生成独立 `runSeed`，候选由种子、奖励序号和已持有内容共同决定，并持久化；同一存档恢复不重抽。
- 保留三选一和跳过奖励。候选至少有一项对当前装备实际有效；保证逻辑在所有快照及空兼容池下有明确回退。
- 酱料可以等待未来换装，但不应三项全是对当前构筑无效的投资。卡片直接列出受影响的装备。

### 7.2 首版八种方向，先实现其中四种

| 酱料 | 规则变化 | 边界与代价 |
| --- | --- | --- |
| 烧烤酱 | 重弹更重；雷阵单次爆炸更集中 | 更慢／覆盖更窄；不增强冰冻控制和回复 |
| 跳跳糖 | 合适弹丸命中后跳向下一敌 | 每次跳跃衰减；单体 Boss 无额外弹射对象时不凭空增伤 |
| 甜酸酱 | 有反弹能力的弹丸碰路沿折向新路径 | 仅指定弹道兼容；导弹、火带和光束不弹墙 |
| 番茄酱 | 直接命中产生小范围溅射 | 不再触发分裂／新一轮溅射；原生爆炸改为较小的半径增益 |
| 辣椒酱 | 直接命中附着灼烧 | 原生尾焰获得有限的持续时间强化，不再额外叠第二份灼烧 |
| 蛋黄酱 | 对未控制敌人施加短暂黏滞 | 不覆盖更强减速；对深冻目标不延长完整冻结 |
| 蜂蜜芥末 | 武器击杀积累维修进度，达到阈值回复 | 有全局回复频率上限；间接击杀归属一致 |
| 奶油咖啡酱 | 完成有效漂移后获得短射速窗口 | 有冷却；不再是全局永久攻速，不增强周期回复 |

首轮原型选四种：甜酸、番茄、辣椒、奶油咖啡。烧烤和弹射待基础武器身份稳定后加入；暴击、拾金、磁吸等数值型收益以后作为模块／普通改装，不占稀少的规则奖励位置。

同名酱料不重复出现。自带同机制时必须有明确、有限的替代收益，例如自带弹射的武器获得一次额外跳跃而不是再次设置同一 bit；若无法提供合理收益，则从当前有效候选中移除。

### 7.3 有效组合的预期结果

| 组合 | 预期变化 | 必须保留的限制 |
| --- | --- | --- |
| 回旋刃 + 甜酸 | 去程碰墙提前折回，玩家换线改变回程覆盖 | 不重置每程命中记录 |
| 重炮 + 番茄 | 直线命中附带小范围清杂 | 空炮仍空，不弥补所有瞄线失误 |
| 尾焰 + 辣椒 | 引导敌人留在火带边缘也能维持灼烧 | 不产生双份持续伤害 |
| 雷阵 + 番茄 | 原生爆炸范围稍扩大 | 不让爆炸再生成另一轮爆炸 |
| 冰冻 + 奶油咖啡 | 漂移后更快积累一次寒意 | 冻结抗性仍生效，不能永久控制 |
| 导弹 + 甜酸 | 不兼容，奖励卡明确说明 | 不为凑组合而让制导弹沿墙无限追击 |

协同是一组共享规则产生的结果，不要求玩家背固定配方，也不强制收齐指定三件才启动。没有核心酱料时，每件基础武器仍应能工作。

## 8. 车辆模块：让驾驶成为构筑输入

三个模块槽不分强制类别，允许进攻、容错和资源之间取舍。同一模块不重复安装，同类触发收益有共同上限。

| 模块方向 | 行为 | 玩家取舍 |
| --- | --- | --- |
| 漂移增压器 | 达到有效蓄力等级后释放漂移，给下一次攻击有限强化 | 需完成真实漂移；连续轻点不触发 |
| 氮气回收器 | 回旋刃接回／击杀指定威胁后积累氮气，通用替代触发为持续安全驾驶 | 鼓励维持节奏；不能让冲刺自给自足无限循环 |
| 应急保险杠 | 安全驾驶积盾；碎盾只给短脱身窗口 | 能容错但不贡献常驻伤害，不兼带环绕绞杀 |
| 车载维修泵 | 一段无碰撞驾驶后缓慢回复 | 选择稳定续航就放弃进攻模块位置；不同时提供击杀回复和磁吸 |
| 应急泄压阀 | 险些被追兵贴身时短脉冲击退，有明显冷却 | 应急救场；持续击退不能自动替玩家走位 |
| 乐园侧翼车 | 作为后续扩展：编队保护一侧，变道后重建队形 | 不在首轮实现，先验证侧翼价值，避免只成为额外枪口 |

首轮只做漂移增压器、保险杠、维修泵。绝境提速暂缓进入首发池：低血收益要等回复、护盾和敌人伤害稳定后独立验证，避免形成主动压低车况却没有可读回报的陷阱选项。

模块作为独立游戏改装服务提供，使用机械名称；不得让同一款餐品在武器目录中是攻击武器，在商店里又无解释地变成维修被动。已有商品被动在迁移时需要明确转换说明。

模块触发只消费标准化驾驶事件，例如有效漂移释放、冲刺开始、安全驾驶区间；不能每帧读取按键并重复触发。

## 9. 商店、MCP 与成长可达性

### 9.1 保留真实菜单，提供独立的游戏改装层

真实商品仍来自开局快照，保留真实商品名、参考价、门店和示例模式标识。当前购买价格还包含升阶倍率及游戏优惠，应明确区分“真实餐品参考价”和“本次游戏花费”。

菜单决定能购买哪些餐品映射，但不能决定玩家是否拥有基本通关工具。另设清晰标注的游戏服务：基础前炮安装、已有武器改装、维修，以及少量原型试装。服务无需额外 MCP 请求，不把虚构商品写进真实菜单。

首轮不增加局外成长货币。酱料来自游戏奖励；改装使用当前金币，避免同时出现金币、零件、经验三条经济线。

### 9.2 三张推荐卡应展示三个决策

优先提供：继续强化当前路线、补足当前弱点、尝试另一种打法。排序考虑具体 weaponId、等级和空槽，而不仅是餐品发现度或“第二轮后优先导弹”。没有相应真实餐品时，显示独立服务卡，不能伪造该店库存。

**同一家店即使推荐卡全部是汉堡，也可以成立。** 例如巨无霸显示贯穿炮、麦香鱼显示跳弹炮、麦辣鸡腿堡显示标记火箭炮，三张卡必须分别展示各自攻击预览。不能为了凑品类多样性，把同品类特色商品藏进二级菜单。

特色推荐应同时考虑餐品发现度和武器机制覆盖。当前后端先选最多 15 件候选，再补足缺少的食品类别，最多核价 18 件；扩展武器后需在相同请求预算内，尽量避免大小份和别名占满名额，保留同家族不同配方。前端无法展示被快照筛掉的特色餐品，因此只改商店排序不够。

“某店特色”仅表达本次已加载门店中的差异，不自动宣称城市独家或官方限定。只有官方数据支持时才使用季节限定等标签。稀有度不等于更高伤害：特色食品可以提供少见攻击方式，也必须有弱点。

升级材料的兜底由改装服务负责，因此不必靠反复刷新真实菜单。首版只提供付费重投（价格随波次与同站连续重投次数上涨），不做复杂锁卡和跨店预订。

替换前显示净花费、损失等级／分支、失去和获得的协同。建议按旧武器累计实际金币投入的 50% 抵扣新装，不能转为可反复套现的金币；赠送装备的投入为零。该比例仅为起测值，需检查早期频繁换装与后期沉没成本。

### 9.3 卡片信息顺序

1. 真实餐品名与专属武器名并列，例如“麦香鱼 → 鱼跃跳弹炮｜前武器”；食品家族作为次级标签。
2. 一句行为与弱点，例如“接回缩短冷却；直线赶路时回程收益较低”。
3. 本次变化，例如“Lv.3：选择宽弧收割／回手连斩”，而非只堆满五行统计。
4. 当前酱料兼容、替换影响、金币净花费。
5. 可展开的伤害、间隔、射程，以及真实餐品来源信息。

停站可播放约 5 秒无伤预览，对照同一组目标展示路线；手机只占卡片区域，不增加操作按钮。

### 9.4 成长节奏目标

第 1 站补全基础前向火力；第 2 波结束获得首次规则强化；首个 Boss 前能感到一个核心方向。第二轮出现首件 Lv.3 分支；第 10–15 波间出现首件 Lv.5 招牌能力。

这是购买可达性目标，尚未测算为平衡结果。需用实际收入、餐品价格区间、维修支出和升级次数验证。若现有升阶倍率达不到该节奏，应先调整游戏改装服务与升级曲线，不能凭空提高真实价格或假设每局都刷到相同材料。

## 10. 四个可实际装下的构筑例子

每例严格遵守 1 前 + 1 后 + 3 模块；酱料不占五槽。下列联动均为提案。

| 构筑 | 前／后武器 | 三个模块 | 关键酱料 | 驾驶循环与风险 |
| --- | --- | --- | --- | --- |
| 回旋走线 | 回旋刃／冰饮 | 漂移增压器、保险杠、维修泵 | 甜酸、奶油咖啡 | 控住追兵后变道接回；不适合在障碍密集时硬追接取 |
| 漂移烧烤 | 贯穿炮／尾焰 | 漂移增压器、保险杠、泄压阀 | 辣椒、奶油咖啡 | 引近追兵铺火带，冲刺脱身后用前炮处理 Boss；长时间远离追兵会丢输出 |
| 诱敌雷阵 | 贯穿炮／雷阵 | 漂移增压器、维修泵、泄压阀 | 番茄、辣椒 | 先布雷再引线；错误变道会让雷阵落空，前炮承担 Boss 伤害 |
| 稳线猎王 | 标记导弹／冰饮 | 保险杠、维修泵、泄压阀 | 番茄、蛋黄 | 控制追兵压力，Boss 恢复时完成锁定；缺少回旋和尾焰的群体清理效率 |

不把任何一个例子做成隐藏套装加成。拆掉一个模块后打法仍可成立，完整搭配只是提高效率或容错。

## 11. 敌人、Boss 与反馈的最小配套

首版不另造大批新怪，先重用已有敌人做出不同阵型：纵列追兵用于贯穿，错列追兵用于回旋，追赶后横移用于尾焰和地雷。阵型必须保留避障空间，不能把高收益输出窗口设计成必吃碰撞。

在现有 Boss 状态机上强化可读的预警与恢复窗口，给稳线武器一次可预期的爆发机会；保留其召唤追兵，确保后武器持续有工作。必要时仅新增一个慢速耐久目标做单体测试，不在武器重构同时扩展完整精英生态。

视觉反馈必须反映真实战斗几何：

- 回旋刃去程／回程外形或拖尾不同；接回有短促音效。
- 火带、雷区和冰雾都显示真正有效的区域、存在时间与方向。
- 导弹显示目标、锁定进度和中断原因；冰冻显示寒意累积与解冻抗性。
- 武器分支有可辨认的炮口／攻击轮廓，不能统一用金色粒子表示一切高级效果。
- 特效在敌人预警、可通行道路和驾驶控件之后让步。首版不以弹幕铺满屏幕作为成型标准。

## 12. 实现边界与迁移建议

本节仅约束后续实现方式，不要求本轮编码。

### 12.1 可保留的基础

继续使用固定物理步长、道路坐标碰撞、扫掠弹丸检测、预分配对象池、自动攻击和波间暂停。菜单快照仍整局固定；不让战斗帧依赖网络响应。

将餐品身份、具体 weaponId、武器家族、攻击组件、升级分支、伤害标签和适用能力放到统一规则表。逻辑、卡片和绘制读取同一份已解析规格，消除“卡片射程／命中射程／特效范围各算一次”的漂移。

32 件武器复用有限的投射、射线、范围场、部署物、旋转体、牵引／锁定等基础组件；按武器分别配置时序、目标策略和专属状态机。工程上的组件复用不等于商品层合并：两件武器可以使用同一弹丸池，但必须保留独立攻击规格与可辨认的行为。

### 12.2 组合规则先写清，再叠效果

- 结算顺序固定为：原型 → 分支 → 酱料与模块修正 → 命中伤害 → 状态 → 有限衍生 → 死亡归属。
- 每个来源携带稳定 ID、根攻击 ID、伤害类型和衍生深度。根攻击 ID 跨弹片／回程仍可追踪。
- 首版衍生深度最多一层：分裂弹片、溅射和连锁不再创造新的衍生攻击。持续伤害不重新触发命中酱料。
- 固有回旋不是衍生生成，可在去／回两程分别命中；碰墙不能刷新阶段命中账本。
- 直接命中、灼烧、溅射击杀统一归属来源。回复与金币收益按击杀结算一次，并遵守各自全局上限。
- 减速取最强效果，不允许较弱黏滞覆盖完整冻结；冻结有刷新上限及解冻抗性。
- 冰冻撞碎属于显式允许的状态联动，最多产生一次冰爆，不重新递归冻结整条敌群。
- 弹射和穿透分别有计数与衰减，不能共用一个数值后宣称二者都能无限叠加。

### 12.3 性能与存档

当前有 256 弹丸、128 敌人和 32 地雷的固定池。首版先在现有容量内限制齐射、火带段、弹片和连爆长度，不直接扩大对象池掩盖问题。驾驶事件、伤害归属和预览数据应在初始化或进站解析，避免逐帧生成临时对象。

池满时优先保留核心攻击，再舍弃额外衍生与装饰；被舍弃的衍生不能继续触发伤害／奖励。不能让高射速辅助攻击长期挤掉玩家的主炮。需要观测每个来源的申请失败率。

存档需要保存原型 ID、等级、分支、模块、酱料、`runSeed` 及已领取奖励。旧档可以从现有商品名／类型推导基础原型，但不能偷偷替玩家选择分支；在下一次安全进站时提供选择。无法可靠迁移时明确提示并保留旧档副本，不直接覆盖。

现有存档未直接持久化变体字段，因此迁移规则应特别验证“跨名称喂养后，原型身份是否稳定”，不要继续依赖随版本变化的名称哈希。

## 13. 分期落地与验收

### 第一阶段：三件技术原型，验证组件与组合

范围：贯穿炮、回旋刃、尾焰；初始散弹的替换试验；漂移增压器／保险杠／维修泵；甜酸／番茄／辣椒／奶油咖啡四酱料。只做 Lv.1–3 和一个完整首轮，提供同场景可切换的测试配置。

尾焰配置配一门基础前炮；贯穿／回旋配置使用初始散弹处理追兵。先证明两侧火力仍有取舍，再加入更复杂的控制和布雷。

**通过条件：** 在相同敌人阵型和相近有效输出下，玩家能说清三件武器分别应怎样发挥；至少观察到两种稳定不同的走线／距离选择。若玩家仍只说“哪个伤害高买哪个”，先改进组件与身份，再推进后续内容。三件是内部验证范围，不是正式武器池规模。

### 第二阶段：12 件可玩武器，验证同品类差异

建议首批编号为 W01/W02/W04/W06/W07、W11/W12/W13、W17、W21/W24、W31，共 12 件，覆盖五个食品家族，其中汉堡至少五种、薯类至少三种。实际餐品可用性在实现前核对。

完成五级分支、模块取舍、商店兜底与替换抵扣。用一个“同店多汉堡、多薯类”的明确标注示例快照，展示全部不同攻击预览；再用真实快照验证映射。同步跑通 20 波与四次 Boss，检查各路线都能清杂并完成 Boss 战，而非只测静态木桩。

此阶段重点验收“巨无霸、双层吉士、麦香鱼买回来真有区别”及“长薯、扭扭薯、薯饼真有区别”。不能只以不同食品家族之间有差异判定通过。

### 第三阶段：32 件内容目标与发现体验

按目录补齐到 32 件已映射、可购买、有独立攻击行为的战斗武器。未核实的候选先替换为实际发现的食品，再完成对应设计；没有实际来源的储备不计完成数。为全部武器建立单独图鉴、卡片预览、升级与兼容规格。

同步完成特色餐品优先发现、同家族机制覆盖、跨门店映射稳定性及移动端回归。原有 28 张餐品美术可复用，但新增武器需要补齐独立攻击轮廓。侧翼车和低血路线另排，不以它们替代几十件餐品武器的交付目标。

### 13.1 如何验证“更好玩”

建议先招募 5–8 名小样本试玩者，覆盖熟悉与不熟悉赛车生存玩法的人。使用相同场景种子，轮换体验顺序，分别记录旧版与原型。小样本用于发现明显问题，不报告为普遍用户结论。

| 验证项 | 起始目标／判断方法 |
| --- | --- |
| 身份辨识 | 每件约 30 秒体验后，多数人能描述其招牌行为和一个弱点 |
| 同类辨识 | 去掉酱料和等级差异，并排比较至少三种汉堡和三种薯类；能区分攻击行为与适用目标 |
| 食品发现 | 在同店多特色餐品场景下，购买不同食品会得到不同 weaponId 与攻击预览；跨店同款保持一致 |
| 操作差异 | 比较换线频率、有效交战距离、刹车与漂移时机；录像能看到差异，不只看问卷 |
| 搭配理解 | 商店选择后能说明“它怎样帮助我现有武器”，不是只读伤害数值 |
| 早期变化 | 第 2 波后已体验一次能说清原因的组合强化 |
| 换装意愿 | 记录试装、放弃和保留旧装的理由，区分沉没成本与真实偏好 |
| 完整可达性 | 对多个菜单快照验证首轮前向火力、分支和招牌能力的获取窗口 |
| 路线存活 | 每条完整路线都可通过首轮；后续有机会通关，不能只靠同一导弹／回复组合 |
| 视觉可读性 | 390×844 模拟视口下能辨认道路、Boss 预警和武器有效区域，再做真机确认 |

### 13.2 技术与平衡验证

采集每件武器的有效伤害、命中目标数、空炮／空雷比例、过量伤害、Boss 伤害占比、控制时长、模块触发、回复量与对象池丢弃率。同步统计驾驶相关伤害，避免把所有收益都算到武器头上。

对每件武器比较“符合其身份的驾驶”和“相同场景的通用直行策略”。策略收益应可重复且有风险代价；若只有增加基础伤害才可达标，说明机制仍未成立。

优先覆盖以下回归：冻结被弱减速覆盖、回旋分程命中、同机制重复收益、间接击杀归属、连爆上限、池满时核心攻击、分支存档恢复、同一存档奖励不重抽，以及手机预警被特效遮挡。

性能目标沿用现有 60 FPS 方向，在指定设备、固定场景和前台运行条件下记录平均帧率、P95 帧时间及长帧；旧版压测结果不能直接当成新版通过证据。

## 14. 内容规模与质量底线

正式方向是几十件餐品专属武器，当前规划目标为 32 件。等级、分支、酱料组合、大小份、贴图换色和纯被动不重复计数。三件技术原型与十二件首批内容是推进步骤，不是缩小最终范围的理由。

每件武器的评审同时回答：**它对应哪款具体食品？它与同家族其他武器有什么机制区别？玩家什么时候会主动选择它？** 在驾驶方式、交战目标、攻击节奏或组合选择上，至少有清楚可见的答案。

暂不并行扩大局外永久数值、复杂套装和新增按键。优先把食品发现、独立武器和酱料协同这条主线做完整。
