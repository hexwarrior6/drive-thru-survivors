## 为什么这个组合会好玩

### 1. "速度即力量" — 赛车与战斗的一体化

不是赛车和战斗割裂成两个小游戏。**漂移加速本身就提升撞击伤害、增加弹丸初速、触发武器特效**——你开得越猛，杀伤力越强。这让驾驶技术直接转化为战斗优势。

### 2. "MCP 变抽卡" — 品牌融入核心乐趣

真实菜单不再是无聊的"购物清单"。每局游戏，MCP 返回的真实餐品决定了你这局能构筑什么 Build：

> "这家店有巨无霸！汉堡炮台！必须买！"
> "只有饮品了……全走冰冻控制流！"

品牌不是贴图，而是游戏机制本身。

### 3. "Brotato 的 Build 毒性" — 停不下来的重玩欲

6 个武器槽 × 同名合成升级 × 餐品类别取舍 = 每局都想尝试不同搭配：

> "如果刚才我选了咖啡涡轮而不是可乐喷泉，也许能多活两波……"

这种"有意义的后悔"是让玩家点下"再来一局"的最强驱动力。

### 4. 短局快节奏 — 适合手机碎片时间

- 每波 45-60 秒，一局完整体验 8-15 分钟
- 死了不心疼（不像掷骰子走了 20 轮才输），立刻想重来
- 单手可玩（虚拟摇杆 + 2 个按钮）

## 对比旧版：根本性差异

| 维度 | 旧版棋盘赛车（codex-6.1-sol） | 新版得来速幸存者 |
|------|-------------------------------|-----------------|
| **操作** | 看字→点确认→掷骰子 | 实时方向键+漂移+冲刺+走位 |
| **技术表达** | QTE 起步 +0/1/2 步 | 漂移蓄力三级释放 + 走位躲弹 |
| **成长感** | 买三件套就没目标了 | 6 武器槽 × 3 级升级 × 无限组合 |
| **反馈感** | 数字变化 + 面板切换 | 爆炸粒子 + 屏幕震动 + 连击计数 |
| **MCP 融合** | "进店买菜"购物感 | "我的薯条散射枪升到 Lv.3 了！" |
| **重玩理由** | 换个骰子结果 | "这次全走饮品控制流试试" |
| **一句话感受** | 在看一个有动画的记账本 | 在开着装满麦当劳武器的赛车屠杀敌人 |

## 旧版失败原因诊断

| 旧版痛点 | 根因分析 | 新版如何解决 |
|----------|----------|-------------|
| 掷骰子决定一切 | 1-6 骰子占移动权重 >70% | 实时操控，玩家技术决定 80%+ 表现 |
| 三件套太容易集齐 | 2-3 家店就买完，后半程无目标 | 无限波次 + 每波都有新武器可升级 |
| 操作就是看字点确认 | 回合制棋盘天然缺乏操作感 | 实时驾驶 + 自动射击，手指忙不停 |
| 提示词过度约束 Agent | 太碎，Agent 拼凑子系统但无连贯感 | "许愿式"提示：高层愿景+技术边界 |
| 缺乏"游戏果汁" | 无粒子特效/屏幕震动/打击感 | 内建完整视听反馈系统 |

## DeepSeek "许愿式编程"方法论

本项目的开发指令借鉴了 DeepSeek V4.1-Flash-1017 的提示词方法论。其 3D 赛车效果惊人的原因是：

1. **零依赖程序化**：明确要求所有资产用代码生成，不链接外部文件
2. **状态机架构**：定义清晰的游戏状态流转，防止做出散乱沙盒
3. **全流程一次交付**：描述"从选车到结算的完整体验"，而非拆成十几个碎片任务
4. **技术手法具名**：说出 `lerp` `screen shake` `particle pool` `object pooling` 等具体技术词，引导 Agent 用正确实现

本项目的 [PHASE_INSTRUCTIONS.md](PHASE_INSTRUCTIONS.md) 严格遵循这套方法论。
